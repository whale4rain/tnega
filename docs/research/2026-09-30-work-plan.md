# Work 模式实现方案

调研日期：2026-09-30。承接 `2026-09-30-computer-use-and-cowork.md`，只讨论 Work（Cowork）的办公产物闭环；Computer Use 不在本期范围。

## 结论

- **管理 Office 文件**：不接 Univer。后端用 Node 库读写真实文件，经结构化工具暴露给模型。
- **预览**：需要。按类型懒加载只读预览器。
- **编辑**：Web 端暂不提供表格编辑；用户通过对话让 Agent 修改。以后需要时再以 Univer 做 xlsx 编辑器。

Univer 的 xlsx 导入/导出属于 `@univerjs-pro/*` 并依赖转换服务，不适合作为本期依赖。

## 选型

| 用途 | 库 | 许可 |
| --- | --- | --- |
| xlsx 读写 | exceljs | MIT |
| 公式求值（供 Agent 校验） | fast-formula-parser | MIT |
| docx 生成 | docx | MIT |
| docx / pptx 读取 | jszip + @xmldom/xmldom | MIT |
| pptx 生成 | pptxgenjs | MIT |
| docx 预览 | docx-preview | Apache-2.0 |
| xlsx 预览 | exceljs 解析 + 自有只读表格 | MIT |
| pptx 预览 | pptxviewjs（Canvas，需 jszip 与 chart.js） | MIT |

不选：`pptx-react-viewer`（解包 44 MB，peer 依赖含 AI SDK、yjs、i18next 等，只读预览过重）、`pptx-preview`（源码收费）、OnlyOffice / Collabora（AGPL/MPL 且需独立服务）、HyperFormula（GPL/商业）、
Office Online 预览（需要公网 URL）。可选增强：检测到本机 LibreOffice 时提供高保真 PDF 预览。

## 架构

- `@tnega/office`：纯库（与 `@tnega/execution` 同类，无 ctx key，不是缝）。按类型提供
  create / inspect / read，xlsx 另有 edit；输入为结构化描述，输出字节或纯数据。
- `@tnega/tool-office`：模型可见工具 `office_create`、`office_inspect`、`office_read`、`office_edit`，
  路径经 `resolveInside` 限制在 Workspace；写入属于工作区写权限。
- CLI：Session 组装 tool-office；新增 `work` agentType 与对应提示；文件接口返回二进制与 `Content-Type`。
- Web：Composer 增加 Work；文件卡片与预览对话框按类型懒加载预览器。

v1 编辑范围：xlsx 支持单元格/公式/增删改 sheet/列宽；docx、pptx 先只支持生成与读取，编辑后续再加。

## 分步提交

1. `feat(office)`: xlsx 生成、检查、读取、编辑。
2. `feat(office)`: 公式求值；docx；pptx，各一个提交。
3. `feat(tool-office)`: 四个工具与测试。
4. `feat(cli)`: 组装工具、`work` agentType、二进制文件接口。
5. `feat(web)`: Work 入口；xlsx / docx / pptx 预览各一个提交。

## 实现状态（2026-09-30）

以上各步已在 `feat/work` 分支按提交落地。实测：模拟模型驱动的 Work 会话经真实 Agent 循环调用
`office_create` 生成 xlsx / docx / pptx，`office_read` 读回公式求值结果；Web 中三种文件卡片可打开预览。
预览器各自懒加载成独立 chunk（exceljs 约 270 KB gzip，仅在打开 xlsx 时加载）。

## 验收

CSV → 带公式的 xlsx + docx 报告：exceljs 可重开且公式与求值正确；Web 中三种格式可预览、可下载；
dispose 后无残留。
