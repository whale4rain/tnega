# Work 模式实现方案

调研日期：2026-09-30。承接 `2026-09-30-computer-use-and-cowork.md`，只讨论 Work（Cowork）的办公产物闭环；Computer Use 不在本期范围。

## 结论

- **生成**：后端用 MIT 的 Node 库生成真实 Office 文件，封装为 Office 能力缝，不先接 Univer。
- **预览**：需要，且有成熟开源方案；按类型懒加载只读预览器。
- **编辑**：v1 不做在线编辑；用户通过对话让 Agent 修改，产生新版本。Univer 放到 v2 作为 xlsx 编辑器。

## 为什么 v1 不用 Univer

Univer 核心为 Apache-2.0，但 xlsx 导入/导出属于 `@univerjs-pro/*`，且需要转换后端服务（见官方 import-export 文档）。
v1 的核心是「生成 → 预览 → 下载」，Univer 带来 Pro 许可、服务部署与大体积前端，却不解决文件交换。

## 选型

| 用途 | 库 | 许可 |
| --- | --- | --- |
| 生成 xlsx（公式、样式、多 sheet） | exceljs | MIT |
| 生成 docx | docx | MIT |
| 生成 pptx | pptxgenjs | MIT |
| 预览 docx | docx-preview | Apache-2.0 |
| 预览 xlsx | exceljs 解析 + 自有只读表格组件 | MIT |
| 预览 pptx | pptx-viewer（ChristopherVR）或 pptxviewjs | Apache-2.0 / MIT |
| 预览 pdf | 浏览器原生 `<iframe>` | — |

不选 `pptx-preview`：npm 可装但源码收费。不选 OnlyOffice/Collabora：AGPL/MPL 且需要独立服务。

## 架构

遵循 ADR 0006 的能力缝：

- `@tnega/office`（Service Definition，`ctx.office`）：`createWorkbook / createDocument / createPresentation`，输入为结构化描述（sheet/cell/公式、段落块、幻灯片），输出字节。
- `@tnega/office-js`（Provider）：exceljs / docx / pptxgenjs 实现。
- `@tnega/tool-office`（Consumer）：模型可见工具 `write_xlsx`、`write_docx`、`write_pptx`，写入 Workspace 并发布到 artifact store（`ArtifactRef` 带正确 mediaType）；`read_xlsx` 读回单元格供 Agent 校验。
- Session：新增 `work` agentType（与 `general` / `coding` 并列），组装 office 工具与文件工具。
- Server：`GET` artifact/文件接口返回二进制与 `Content-Type`，支持下载。
- Web：Composer 增加 Work；`ArtifactViewer` 按 mediaType 分发到懒加载的预览组件；消息时间线里工具结果显示文件卡片，点开预览。

## 分步提交

1. `feat(office)`: Service Definition 与类型、测试。
2. `feat(office-js)`: xlsx Provider + 重开校验测试；随后 docx、pptx 各一个提交。
3. `feat(tool-office)`: 工具与 artifact 发布。
4. `feat(cli)`: `work` agentType 组装与二进制下载接口。
5. `feat(web)`: Work 入口；随后 docx / xlsx / pptx 预览各一个提交。

## 验收

CSV → 带公式的 xlsx + docx 报告：文件可被 exceljs 重开且公式存在；Web 中三种格式可预览、可下载；dispose 后无残留。
