# Project 产品形式重新对齐（已由 v2 设计取代）

> 状态：过渡记录；已由 [Project v2 设计框架](./2026-09-25-project-box-blackboard-design.md) 取代。

日期：2026-09-25。依据 [新版 Claude Projects 一手资料核对](../../research/2026-09-25-claude-projects-redesign.md)及用户截图。本稿描述 Tnega 应提供的使用体验，不指定技术实现。

## 目标形式

一个 Project 是一段持续的主对话。用户随时提出工作、补充要求或问进度；协调 Agent 判断是在这里直接回答、把工作交给已有 Thread，还是启动新的 Thread。每次分派都在主对话的相应位置留下可打开的 Thread 卡片。Thread 独立执行并回报；用户可从卡片或 Overview 打开 Thread，查看完整过程并直接干预。

这一结构来自 Anthropic [2026-09-17 新版公告](https://claude.com/blog/projects-redesigned)。截图显示主对话居中，右侧打开一个 Thread；它是界面参考，不足以证明画面中的任务清单属于独立的项目级任务系统。

## 用户路径

1. 建立 Project，填写名称与初始目标或背景，直接进入主对话。环境、资料和模型允许之后逐步完善。
2. 用户发消息。协调 Agent 可以原地回答，也可委派一个或多个 Thread，并在对应消息下显示每个 Thread 的名称与状态。
3. 用户继续在主对话交代工作。协调 Agent 可以复用相关 Thread，也能开新 Thread，并明确告知路由结果。
4. Overview 是可打开的状态面板，显示正在工作、等待用户、等待审阅和已经结束的 Thread；它不取代主对话。
5. 用户打开 Thread，查看执行记录、结果并直接留言，回答权限请求或中止。回到主对话时，卡片仍在原处并显示最新状态。
6. Project 保留共享资料、稳定指令、采纳的决定和产物。新 Thread 取得相关上下文；产物可从项目层检索。

## 对象边界

| 对象 | 用户能感知到的职责 |
| --- | --- |
| Project | 持续工作空间，承载主对话、Thread、共享上下文和产物。 |
| 主对话 | 用户与协调 Agent 的默认入口。小问题可在此回答，分派、汇报和跨 Thread 决定在此可见。 |
| Thread | 可独立运行、查看并直接干预的一件工作，有自己的执行历史、模型和专业工具。 |
| Overview | 对已有 Thread 的状态投影和入口，不是一条对话，也不是默认首页。 |
| Library | 项目级资料和产物入口，保留来源与版本，供 Thread 引用。 |
| Eval / Review | 对需要证据的交付进行评测与审阅；一般问答不强制走正式验收流程。 |

Thread 与短时 Subagent 不合并。Thread 可以在主对话之外持续存在，用户能直接进入并继续交互；Thread 内部仍可调用有界 Subagent。协调者的工具保持精简，专业工具按 Thread 能力配置安装。

## 当前实现与目标体验的差距

| 当前实现（`codex/project-collaboration`） | 需要调整的产品行为 |
| --- | --- |
| `ProjectOverview` 是默认整页，先展示目标、设置、预算和线程分组，再嵌入 `ProjectChat`。 | 默认入口改为主对话。Overview 按需打开；设置与预算放在次级入口。 |
| `ProjectChat` 只按普通消息渲染执行日志；Thread 从旁边的列表进入。 | 主对话的分派需要生成关联到消息位置的 Thread 卡片。现有 `createdByThreadId` 只能说明来源线程，缺少消息级关联。 |
| `ProjectOverview` 对所有 `project.threads` 分组。 | 协调者主对话从执行 Thread 列表分离，避免被当作一项待完成任务。 |
| 创建表单要求先选 Workspace Git 来源和四种角色的模型。 | 用户应先建立可交谈的 Project；仓库来源、专业角色、模型和预算的设置时机与默认值需重排。 |
| Worker 提交后进入 `awaiting_review`，再由协调者验收。 | 有交付物的任务保留正式验收；一般问答和无需审批的工作可自然结束并回报。 |
| 已有产物版本和决策索引，界面以 Delivery / Attention 面板呈现。 | 增加项目级 Library 入口，并连通主对话卡片、Thread 结果与产物。共享记忆的写入和读取边界仍需定义。 |

这些是根据当前代码作出的 Tnega 设计判断。Project Log、独立 Session、协调者和 Worker 作用域、权限与预算机制仍有复用价值；具体对象需按新的交互契约复核。

## 第一轮范围建议

先跑通“创建 Project → 持续主对话 → 新建或复用 Thread → 消息内卡片 → 侧边查看并干预 → 回报进入主对话 → Overview 查看待处理事项”。Library 至少列出已发布产物，并能从 Thread 定位过去。模型和工具差异沿用已有能力，不作为首次使用的必填配置。

云端常驻、多仓库、GitHub PR 自动处理、定时任务和跨用户共享都不能从截图推断为首期需求。Tnega 当前是本地产品；关闭网页后是否继续运行取决于宿主进程，电脑关闭后仍工作则需常在线运行环境。

有两处产品选择还需确认：首期是否支持没有 Git 仓库、只用资料启动的 Project；共享记忆是只收录明确采纳的信息，还是允许系统自动整理并提供纠错入口。这些选择会影响创建流程和持久化。
