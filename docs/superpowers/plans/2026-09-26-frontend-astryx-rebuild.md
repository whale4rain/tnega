# Frontend Astryx Rebuild Implementation Plan

> **For agentic workers:** Execute inline with focused checkpoints. Follow the phase order below; each phase is independently reviewable and committed before starting the next.

**Goal:** Rebuild Tnega's React frontend progressively around Astryx while preserving its current workbench information architecture and user-visible behavior.

**Architecture:** Keep `App.tsx` as the application state and routing/selection composition layer. Migrate the shell first, then each existing surface by composing Astryx components at the UI boundary without moving data or session behavior into library wrappers. Keep application-specific components only for Tnega workflows or behavior that Astryx does not supply.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind CSS 4, Astryx (`@astryxdesign/core`, theme package, StyleX peer dependency, CLI).

**Spec:** `docs/frontend-astryx-rebuild.md`

## Global Constraints

- Preserve left workspace/session navigation, the main conversation/project area, and the optional right tool panel.
- Prefer existing Astryx components; do not create a new component where Astryx provides a suitable one.
- Rebuild in the order overall layout, local components, full application integration.
- Remove obsolete presentation-only frontend tests when their corresponding UI is replaced; preserve reusable state, event, API, and persistence tests.
- Do not add tests that only restate reversible, low-impact implementation details.
- Commit each independently reviewable phase with a Conventional Commit message of at most 72 characters.
