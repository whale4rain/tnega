# Tnega v0.4.21

## Features

- **Compact density.** Controls, list rows and tool rows are shorter, the
  session title and workspace share one line, the top bar matches the desktop
  title bar, and icons use thin 14 / 12px strokes. Colors, weather states and
  contrast are unchanged.
- **Sidebar by workspace.** Each workspace is a collapsible group listing its
  Projects, then its most recent Sessions (8 by default, the rest under
  "N more"). Opening an item in another workspace switches to it; collapsed
  state is remembered.
- **Role-scoped Project tools.** The coordinator only dispatches and manages
  Project knowledge (no shell, file writes or background jobs); Threads no longer
  see routine tools, and Threads at the depth limit no longer see
  `spawn_thread`. Requests carry fewer tool definitions and cache better.
- **Cheaper collaboration.** The coordinator ends its turn after dispatching,
  stops polling Threads and re-checking their work, and receives bounded
  reports. `spawn_thread` gains `on_report` to wake it only when a next step
  depends on the result. On DeepSeek the same task fell from about 235k to
  about 89k prompt tokens and from about 150 s to about 43 s.
- **Compact Project screens.** A one-line Today strip, Needs you / Working /
  Ready lanes with Idle and Resolved folded, shorter cards, one-line Thread
  cards with avatars, live steps such as "Editing count.mjs" for Threads
  without a checklist, and folded long coordinator messages.

## Fixes

- **Automatic approval on thinking models.** Reviews get a 4096-token budget and
  read JSON decisions wrapped in code fences or prose, so DeepSeek and similar
  models no longer escalate every request.
- **Bounded Project messages.** `send_project_message` is limited to 600
  characters and points long reports to `publish_artifact`.
- **Sidebar footer.** "Add workspace" is an icon button and no longer overlaps
  the theme switch.

## Install

```bash
npm install -g tnega@0.4.21
```

Windows: download **Tnega-Setup-0.4.21.exe** from this release, or let an installed client update itself (Settings → Check for updates).

Existing model configurations, Projects and Sessions need no migration.
