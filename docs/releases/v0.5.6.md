# Tnega v0.5.6

This stable release gathers everything since 0.5.5, including the two 0.5.6
previews: an agent that can ask for a secret it uses but never sees, a command
sandbox it can ask to open one domain at a time, and computer use — an agent
that reads a window's accessibility tree, aims at elements instead of guessing
pixels and reports what its action changed — with images moved out of the
request body. Computer use ships off by default and needs the `cua-driver`
binary installed separately.

## Features

- **The agent can ask for a secret without seeing it.** When a task needs a key,
  the agent asks with `ask_user_question` and a `secret` name such as
  `GITHUB_TOKEN`. The question card is a single hidden input with a show/hide
  toggle and a **Remember** button; the value goes straight to the host's secret
  store, and the agent only learns the name. Commands get it as an environment
  variable, so `$env:GITHUB_TOKEN` (PowerShell) or `$GITHUB_TOKEN` works. A
  session secret lives until the session is deleted or tnega exits;
  **Remember** saves it for the workspace in `~/.tnega/secrets.json`
  (owner-only, `0600`) so every session there starts with it. Settings → Secrets
  lists the names and removes one; it never shows a value, and secret values are
  masked in tool output and live progress as `[secret: NAME]`, plain and in
  base64, base64url and URL-encoded form. A value a command was given stays
  masked even after the secret is removed or replaced.
- **Command network rules.** Settings → Tools & shell → Command network chooses
  what sandboxed commands may reach: `open` (unchanged behaviour), `off`, or
  `allowlist` with allowed and denied domains. An allowed entry is `example.com`,
  `*.example.com` (subdomains only), an IP literal, or any of those with `:port`
  or `:*`; deny wins over allow, and anything unlisted is refused. **No port
  means every port** in both lists: `example.com` and `example.com:*` are the
  same, while `example.com:443` matches only 443. Each command reaches the
  network through a filter proxy the host runs on loopback — Linux gets it over
  a bind-mounted Unix socket, macOS and Windows over a loopback port that the
  sandbox permits — and allowed connections can chain through the network proxy
  already set in Settings. A refused command's stderr names the blocked host and
  says to ask the user. The command's traffic is filtered at the destination
  level only: allowing `github.com` allows everything inside that tunnel, and a
  client that ignores proxy environment variables simply has no network.
- **The agent can ask for a blocked domain.** `request_network_access` exists
  only where the host can read and write those settings; it always goes through
  the approval card, and an approved host applies to the rest of the session,
  while **remember** also writes it to Settings. `off` and the deny list cannot
  be opened by an approval, and `*` is never granted.
- **The agent can see and use desktop apps.** Computer use adds `ctx.computer`
  and a `computer_*` tool family: list windows and apps, start an app by name,
  id or executable path, screenshot a window, zoom into a region, then click,
  type, press a key, scroll, drag, hover, invoke a menu item, run a batch of
  steps, read and write the clipboard. It is off until **Settings → Computer
  use** is on, and it needs the `cua-driver` binary (not bundled): the host looks
  for `computerDriverPath`, then `TNEGA_CUA_DRIVER`, then `PATH`, then the
  installer's folder, and fails with an install command rather than falling back
  to another input path. Actions default to background delivery and only retry in
  front when the driver refuses the event kind — a re-sent event is how one
  keystroke becomes two.
- **Aim at elements, not pixels.** `computer_read_tree` reads a window's
  accessibility tree as text, each actionable row tagged `[N]` with an element
  token `<snapshot>:N`; click, scroll, type and single keys take that token
  instead of a point, so the driver invokes the element itself and can confirm
  the result. Element and point are mutually exclusive. A token from an older
  read is refused with a hint to read again, never silently retried. This costs
  no screenshot.
- **An action says what it changed.** When the driver cannot confirm an effect,
  the result carries the driver's own comparison with the caller's previous read:
  `3 added, 0 changed, 1 removed` plus the differing rows, or an explicit
  "the window did not change" — including, for posted input on a target that may
  ignore it, a warning that the click probably did not land. A change that shifts
  rows also reports the renumbering, so old tokens are not reused. A confirmed
  action pays nothing extra.
- **Row boxes on request.** `computer_read_tree` accepts `frames: true` to append
  each row's box in the pixels an action takes, for grids, rows and columns, and
  for popup rows that carry no element token. It costs one screenshot per read.
- **Hover, clipboard, apps, menus and batches.** Hover moves the *real* pointer
  (a window-scoped cursor is an overlay apps never see), with the window brought
  forward. Clipboard read/write share their own `computer:clipboard` grant.
  `computer_list_apps` names each app's id so "chrome" means that app.
  `computer_menu` resolves a native application menu by label path; menus a page
  or an Electron or WinUI app draws itself are not supported and say so.
  `computer_steps` runs several actions in one call, judged step by step, and
  each step that ran is audited.
- **Computer use runs without a prompt, and a risky step still asks.** The agent
  drives apps on its own by default; every acting tool takes an optional `risk`
  reason, and a call that carries one needs a person's approval for that call,
  with the reason on the card. Settings → Computer use → **Computer use
  approvals** puts the old behaviour back (**Ask once per app in each session**),
  and **App limits** caps one app at `look` (screenshots and reading only),
  `click` (no typing, keys or drags) or `full`; apps are not listed as `full`,
  names ignore case, folder and `.exe`, and a display name such as `Google
  Chrome` covers `chrome.exe`. With limits set, a window whose app cannot be
  identified is refused rather than allowed.
- **A hint says which driver computer use needs.** When the driver is missing,
  a dismissible line above the chat names the install command and links to the
  docs, and adds the Settings switch to its wording when computer use is off.
  `GET /api/computer/setup` answers from a filesystem check alone — the same
  lookup the Provider does, without starting anything.
- **Screenshots are budgeted per Session.** `computerMaxScreenshots` bounds the
  screenshots one Session may take; screenshots, zooms, waits and the image after
  each action all count. The count is rebuilt from the Session's own tool
  results, so a restart does not refill it. Once spent, actions still run but
  answer without an image, and the looking tools point at `computer_read_tree`.
- **Text-only models get the tools without screenshots.** The host answers
  whether the model behind the next step can see images, asked before every
  screenshot because the model can change mid-run; when it cannot, results
  describe the window in one line and spend no budget.
- **Images no longer travel in the request body.** Screenshots and other images
  are uploaded once to the route's Files API (keyed by SHA-256, so the same bytes
  are uploaded once and the id stays stable across turns) and referenced by id:
  `{type:"file"}` for chat completions, `input_image.file_id` for Responses, and
  a file source with the `files-api-2025-04-14` beta for Anthropic. Measured on a
  1024 screenshot: 402 KiB uploaded once, request body down from ~400 KiB to
  138 bytes, and a sliding image window no longer changes the prompt prefix.
  `filesApi` (`auto` / `off` / `required` / `openai` / `anthropic`), `filesUrl`
  and `filesPurpose` control it; an endpoint without a Files API is remembered
  instead of retried every turn.
- **`maxImages` bounds the images a request carries.** Set it at the top of the
  config or on one model route (the route wins). Each image is billed again on
  every request, so a screenshot-heavy task wants a small number: 2 is enough for
  computer use.
- **Responses turns can chain.** With a route that keeps state, the adapter sends
  `store` and `previous_response_id` and only the new turns; only a strict prefix
  of the conversation is chained, so a compaction or an edited message resends
  everything. A route that says it did not store the response turns state off by
  itself, and DeepSeek's stateless Responses endpoint is never sent those
  parameters at all.
- **The Context tool shows what each tool cost.** The session context report has
  a per-tool row: calls, failures, time, images its results carried, and the
  prompt and completion tokens of the requests that read those results, split
  evenly when one request read several. The Context tool lists them under
  "By tool".

## Fixes

- Projects mode no longer lists the secrets of a session that is not on screen,
  and a saved secret named `__proto__` is kept while inherited names such as
  `toString` are no longer reported as removed.
- Secret names that would change what a command loads or runs are refused:
  families `LD_`, `DYLD_`, `NPM_CONFIG_`, `JAVA_`, `_JAVA_`, `GIT_CONFIG_`, plus
  `JDK_JAVA_OPTIONS` and the Git variables that steer execution. `GIT_TOKEN` and
  similar names still work. A damaged or unexpected `secrets.json` reports its
  path instead of being silently dropped on the next save, and rewriting it keeps
  every workspace's keys.
- The command filter proxy refuses a host it is about to block **before** it
  resolves it, so a blocked name never leaks to DNS, and it also refuses cloud
  instance-metadata endpoints outside link-local (`100.100.100.200`,
  `168.63.129.16`, `192.0.0.192`, `fd00:ec2::/32` and similar) plus the host's own
  interface addresses. Both stay recoverable: a rule that names the host
  literally skips that check, so allow-listing `192.168.1.10:3000` works while
  `*.corp.internal` does not.
- WebSocket traffic works through the filter proxy: an upgrade request used to
  reach the origin as an ordinary request and come back `200`, leaving the client
  stuck after "connected". A refused command's note also describes only that
  command, so a background job hitting a different host no longer sends the agent
  after the wrong domain. An approval cannot widen a narrower policy, and a
  network setting saved after a run starts is still honoured.
- One refused image no longer costs a route its vision. Only an error about the
  model's own input (`does not support image`) counts; a rejected upload, a file
  id this account does not own or an oversized image is a problem with that
  image, and a different set of images is tried again rather than staying
  text-only for the life of the adapter.
- A route's `fetch` covers every request it makes — completion, upload and model
  list. Previously only the upload used it, so an injected transport saw the
  upload and the completion escaped to the global fetch.
- A minimized window is restored before it is read or acted in, and input the
  driver delivered but could not confirm is never re-sent. Hover is refused
  outside the window's screenshot instead of moving the user's pointer onto
  another window, and no action targets rows a diff read marks as removed. A
  change summary keeps the driver's renumbering note, so a model does not follow
  stale `[N]` rows.
- A screenshot slot is held before capturing, so screenshots taken side by side
  cannot overrun the budget, and a cancelled app-limit lookup reports itself as
  cancelled.
- A click the agent flags as risky is never answered by a grant, reviewer or
  delegate: with nobody to ask it is refused, and the window's owner is looked up
  on every action so a reused process id cannot inherit an old answer.
- A capability that fails to load no longer takes the whole scope with it. A
  broken office package would have abandoned every capability queued behind it,
  leaving a run with no tools; the failure is now contained to that one
  capability and its reason goes to stderr and the context logger.
- `TNEGA_HOME` isolates the settings file too: `systemConfigPath()` used to go
  straight to the home directory (and ignored `TNEGA_HOME` entirely on Windows),
  so a throwaway or isolated installation read and wrote the person's own
  `config.json`; the legacy `%APPDATA%` import now skips an isolated home.
  Global memory already follows the same rule, so it is no longer read from the
  developer's `~/.tnega/MEMORY.md`, and the "memory is full" error names the file
  it refused.
- `tnega run` reads the image budget from the route it actually uses, not the
  top-level setting.
- A live browser view whose screencast lost the navigation race recovers instead
  of staying blank, and an agent's teardown is awaited when its Context is
  disposed.
- Leaving a session no longer keeps the previous summary on screen while the next
  one loads (a settings change made then went to the session that was left), an
  older page still loading for the session just left no longer holds back
  polling of the session now open, and a remote run is polled one read at a time
  so long logs no longer stack up and replace the window out of order.
- Text typed while a send settles is kept, new-conversation drafts are kept per
  workspace, and a history page dropped by a reload is asked for again while the
  reader is still at the top.
- The Workbench stays within half the window (320 px floor) and its saved width
  applies after a reload again; the desktop window can shrink to 640 px to sit
  beside another window. A background job's report is shown as a notice in the
  turn it wakes ("Background job failed: npm run dev") instead of as a message
  from the person.

## Other

- The test suite is split into two layers: `pnpm test` runs the code layer (no
  credentials, build artifact, GUI or elevated privilege), and
  `pnpm test -- --全量` (or `pnpm test:all`) adds the host layer as a second
  sequential pass. A test joins the host layer by being named `*.e2e.test.ts` or
  `*.smoke.test.ts`. The release gate runs both layers, and keeps the default
  per-test budget so running everything cannot be more lenient.
- Long sessions are lighter: history reaches the web client without the streamed
  chunk copies that made up over 90% of a page (39.5 MB to 1.6 MB for one 40 MB
  session, and eight long sessions stay cached instead of three), the web client
  re-renders only the live turn while streaming and keeps off-screen turns out of
  layout, and the office tools are loaded only when a workspace has an office
  file, which cut a cold CLI start and the suite by half a minute.
- New packages: `@tnega/secrets`, `@tnega/secrets-local`,
  `@tnega/execution-secrets`, `@tnega/tool-secrets`,
  `@tnega/sandbox-network-proxy`, `@tnega/tool-network-access`,
  `@tnega/computer`, `@tnega/computer-cua`, `@tnega/computer-tiers`,
  `@tnega/tool-computer` and `@tnega/llm`'s Files API module, all published as
  `tnega/*` subpaths. `@tnega/sandbox` gains the `network` policy dimension,
  `decideNetworkAccess` and the `sandbox/network` event.
- ADR 0015 records the secret store's format, lifecycle and permission boundary;
  ADR 0016 records the computer seam, the element pathway, the feedback loop, the
  default-allow policy with app tiers, and the driver's menu limits; ADR 0008
  records the command-network dimension and its local address set.
- This stable release promotes the 0.5.6 previews (beta.1 and beta.2). npm
  publishes it to `latest`; desktop clients on the Stable channel update from
  `latest.yml`.

## Install

```bash
npm install -g tnega@0.5.6
```

Desktop: download **Tnega-Setup-0.5.6.exe** (Windows), **Tnega-0.5.6-arm64.dmg** / **Tnega-0.5.6-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.6-x86_64.AppImage** / **Tnega-0.5.6-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.

Computer use needs the `cua-driver` binary from <https://cua.ai/docs/cua-driver>; it is not bundled, and the tools stay hidden until you turn it on in Settings. A client on the Preview channel moves to this release as well; switching back to Stable changes future updates only.
