# Tnega v0.4.15

## Features

- **Daily usage calendar.** Settings → Usage shows a heatmap and dated response details for Sessions, Project coordinators and Threads, including model, input/output/cache tokens and cost. Model changes follow Session settings. Both themes and narrow screens are supported.
- **Workspace instructions.** Settings → Instructions saves or clears a custom system prompt for subsequent requests, including resumed Sessions and Project Threads, without restarting.
- **Automatic Session names.** After the first successful reply, the current model generates an intent summary. Names persist across reloads; manual names take priority. Failed or timed-out naming keeps the default.
- **Background completion sounds.** Web and desktop stay silent while focused. Background completions play a soft chime, with simultaneous notices coalesced. Desktop focus includes the embedded Browser panel.
## Fixes

- **Interrupted Sessions reopen reliably.** Recovery closes all declared pending tool calls with visible interrupted results, including reused call IDs. Tools can provide retry or confirmation guidance; recovery never automatically replays side effects.
- **Invalid tool arguments fail before execution.** Nested arrays, undeclared properties and declared numeric/length bounds are validated. Errors remain visible to the user and model so the next call can be corrected.
## Other

- **Documentation updates.** The README uses the current cloud icon, and release history consistently groups Features, Fixes and Other.

## Install

```bash
npm install -g tnega@0.4.15
```

Windows: download **Tnega-Setup-0.4.15.exe** from this release, or update through Settings → Check for updates.

This is a stable release. Use Settings → Update channel → Stable.

Existing Session logs remain compatible. Tool interruption policy fields are optional and default to failure; no log-format migration is needed. Workspace instructions use the existing home state location. Close older desktop/CLI processes before using the updated client so both versions do not write to the same histories. Automatic naming makes one additional short model request per eligible new Session.
