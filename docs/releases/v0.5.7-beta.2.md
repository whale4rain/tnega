# Tnega v0.5.7-beta.2

## Features

- **A server several people sign in to**: `tnega server init`, `start` and `deploy` keep Sessions in Postgres, issue device tokens for browsers and daemons, and seal remembered secrets with a master key. Owners and admins manage people; members work only inside their own folder, and their commands stay sandboxed even when an escalation is approved.
- **Each person's sessions run in a box of their own** (gVisor, no KVM needed): every signed-in person gets one box per workspace, with its own network namespace, an egress proxy that allows only the hosts in `.tnega/environment.toml`, and no secret values inside. Files, commands and search go to the daemon in that box, so the Workbench, change tracking and skills see the same folder. Boxes pause when idle and come back on the next run; a restarted server finds them and their daemons dial back in on their own.
- **`tnega daemon` pairing** for serving a folder from your own computer to a server, with devices listed and revoked per person.

## Fixes

- gVisor boxes start with `run --detach` on current `runsc`, keep their own network per box, and report why a start failed instead of failing silently.
- A box is its own sandbox: commands in it no longer ask for a second sandbox the template does not have, so `read-only` sessions and members run normally.
- A gVisor box runs as the owner of the folder it mounts, so `/workspace` is writable and files stay that person's; `/etc/hosts` is mounted read-only from the host, and the start script keeps its certificates in a folder the box owns when it is not root.
- Idle pauses are re-armed at startup for boxes that were running when the server stopped, so they still pause on the same clock.
- Sign-in rate limits count the address the proxy added, and members' escalated commands stay in the sandbox.

## Other

- The gVisor box host must run the server process as root (namespaces, `nft`, cgroups); `docs/guide/server.md` now has a systemd unit and says boxes themselves run as the folder owner without capabilities.

## Install

```bash
npm install -g tnega@0.5.7-beta.2
```

Desktop: download **Tnega-Setup-0.5.7-beta.2.exe** (Windows), **Tnega-0.5.7-beta.2-arm64.dmg** / **Tnega-0.5.7-beta.2-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.7-beta.2-x86_64.AppImage** / **Tnega-0.5.7-beta.2-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.
