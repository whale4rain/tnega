# Tnega v0.5.1

## Features

- **Choose what a running reply shows.** While the agent works, the reply itself
  ends with a **Process output** switch: **Steps** (the default) streams the
  narration, its thinking and every tool step as they happen, and **Answer only**
  keeps a single progress line until the turn ends, when the answer arrives. The
  steps stay one click away, and the choice is remembered on this device.
- **The terminal client can be driven without memorising keys.** A hint row under
  the prompt names the keys that matter right now, `?` on an empty prompt lists
  them all, and the box's top border shows the line count and a non-default mode.
  `Tab` or `Alt+Enter` queues a message to send when the current run finishes
  (queued messages sit above the box; `Up` takes the newest back, `Ctrl+X` drops
  it), and `Shift+Tab` cycles auto, plan and goal. `tnega --help`, `-h` and
  `help` list every command, each command takes `--help`, `-v` prints the
  version, and a bare `tnega` opens the terminal client (printing help with exit
  code 2 when its output is piped).
- **The terminal client shows the weather.** A session opens with the brand cloud
  and the status line carries the coloured weather strip, so what the agent is
  doing reads at a glance. `TNEGA_REDUCED_MOTION=1` stills both.
- **Threads report back like a colleague.** A Thread's reply is a short paragraph
  with links; steps, commands and raw output stay in its checklist or an artifact.
  The coordinator's brief folds to one "Message from Coordinator" line that opens
  on click.
- **Reactions.** Messages in a Project room and in Threads take emoji reactions
  from you (a hover button and chips) and from Agents
  (`react_to_message`). They are stored as facts and never wake an Agent.
- **Plugin dev mode** (`tnega web --plugin-dev`, `tnega tui --plugin-dev`, or
  `TNEGA_PLUGIN_DEV=1`) lets an agent write its own single-file plugins into
  `~/.tnega/dev-plugins` and hot-mount them: `plugin_write` puts a plugin live in
  the next step of the same run, with `plugin_read`, `plugin_list` and
  `plugin_remove` beside it. Off by default. Plugins run in the host process, so
  writing and removing them asks for approval outside bypass.

## Fixes

- The agent finishes more of what it starts instead of handing a half-done job
  back. A reply that trails off on a lead-in with no closing punctuation
  ("… and now", "…, then", "接下来") is read as cut short and the agent is asked
  to continue, and a turn whose step budget runs out right after a tool call now
  gets one last step to read those results and report. Replies that end on
  markdown emphasis or an emoji count as finished, so they are left alone.

## Other

## Install

```bash
npm install -g tnega@0.5.1
```

Desktop: download **Tnega-Setup-0.5.1.exe** (Windows), **Tnega-0.5.1-arm64.dmg** / **Tnega-0.5.1-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.1-x86_64.AppImage** / **Tnega-0.5.1-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.

npm publishes this version to `latest`; desktop clients on the Stable channel
update from `latest.yml`, and clients on Preview move to it too.
