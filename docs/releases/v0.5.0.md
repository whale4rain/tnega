# Tnega v0.5.0

## Features

- **Mac and Linux desktop apps.** Download a `.dmg` for Apple silicon or Intel,
  or an `.AppImage` / `.deb` for Linux, from the same release as Windows. The
  Mac app keeps its menus, puts the window controls in the top-left header and
  reopens from the Dock.
- **A calm new look.** Carbon, a neutral grey theme with an ink accent, is the
  default in light and dark; Sky, Sand, Forest and Graphite stay selectable.
  Geist and Noto Sans SC set the interface, JetBrains Mono the code, and a
  Fraunces serif greets new sessions and the Project Board.
- **A quieter sidebar.** Each row is a dot and a title. Projects from every
  workspace are pinned at the top with their status light and pull-request
  state, Pinned folds after 8, and a project's "…" menu can archive, restore or
  delete it.
- **No folder needed.** New sessions start in a scratch folder
  (`~/.tnega/scratch`, shown as "No folder").
- **The Workbench is a card** inset from the window edges. On the desktop its
  tabs and the header actions sit beside the window controls.
- **Project Board.** It opens with a greeting, a plain-sentence status and a
  one-line recap, with cards for threads, outputs and pull requests that open
  where they point.
- **Projects work like a team.** Each Thread works in its own Git worktree and
  delivers one pull request. Project memory is extracted in the background
  within daily limits. Artifacts open as a page beside the Thread that made
  them, with follow-ups on selected text and kept revisions. Coordinator
  messages to a Thread show in its chat.
- **Pick up after a crash.** Sessions and Project Threads cut off by a crash or
  restart continue where they stopped and check tool calls that may already
  have run. Sending is safe to retry, and only one process writes a session.
- **Thinking folds away.** The model's reasoning shows as a muted "Thought" row
  that folds when the answer starts.

## Fixes

- Long tool commands shorten to one line and show in full on hover or when
  expanded, instead of being cut off at the edge.
- Selected cards and the Workbench resize line no longer show a bold white
  frame in dark mode.
- Dialogs take clicks on the desktop, so their close button works, and they
  start below the window controls.
- Stop ends a running tool call promptly, including MCP calls that never answer;
  an interrupted `shell` command reports what it printed so far.
- DeepSeek in thinking mode no longer rejects tool loops with a 400 error.
- Windows desktop no longer freezes or hangs the first time a workspace is
  sandboxed, and a folder the sandbox may not change fails with the reason
  instead of `Win32 5`.
- Reopening a crashed session repairs only the torn tail and keeps a copy of a
  log damaged in the middle.
- Switching workspaces or reopening a project no longer blanks the screen while
  the new data loads; draft pull requests show as drafts.

## Other

- **Sessions store the model's reasoning.** A session written by this version
  can't be opened by 0.4.24 or older. Project Thread worktrees need `git`; pull
  request delivery and status need the GitHub CLI (`gh`) signed in.
- **The macOS app is not signed with an Apple Developer ID.** If macOS refuses to
  open it the first time, go to **System Settings → Privacy & Security** and
  choose **Open Anyway**. It can't replace itself, so it shows
  **Download** instead of **Update** and opens this page. The Linux binary is
  `tnega-desktop`, so the `.deb` does not shadow the npm `tnega` CLI.
- **Release gate.** The release workflow now builds and launches the Mac and
  Linux packages before publishing; if one of those jobs fails, nothing is
  published, Windows and npm included. Check the `desktop` jobs in the Release
  run after tagging.

## Install

```bash
npm install -g tnega@0.5.0
```

Desktop: download **Tnega-Setup-0.5.0.exe** (Windows), **Tnega-0.5.0-arm64.dmg** / **Tnega-0.5.0-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.0-x86_64.AppImage** / **Tnega-0.5.0-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.

This stable batch includes every change since 0.4.24, including the 0.4.25
previews. npm publishes it to `latest`; desktop clients on the Stable channel
update from `latest.yml`, and Preview clients move to it too.
