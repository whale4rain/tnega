# Tnega v0.4.7

- **Session storage.** Desktop, Web and default CLI logs, subagents and Project Thread histories now live under `~/.tnega`, partitioned by Workspace path. `TNEGA_HOME` can override the storage root. Project configuration, skills, memory and artifacts remain in the Workspace.
- **Migration.** Existing project records are imported on first access, with originals retained as backups. Close older desktop and CLI processes before using this version. Conflicting copies or continued legacy writes are reported rather than overwritten. Session format remains v10; relocation does not convert unsupported formats.
- **PTC.** Fix packaged desktop execution failing with `Cannot find module ... app.asar/out/worker.mjs`; the worker and QuickJS WASM resolve from the shipped runtime resources.
- **Changed files.** Session logs, internal Project records and spill output no longer appear as source edits. Workspace configuration, memory, skills and artifacts remain visible. Fix paths for Workspaces nested in larger Git repositories.
- **Update channels.** Settings offers Stable and Preview (pre), remembers the selection and invalidates pending updates from the previous channel. Returning to Stable does not downgrade an installed preview. This release is stable and uses `latest.yml`.
- **Reliable updates.** Desktop releases carry the installer, blockmap and matching update feed. Release tooling supports future beta previews with their own feed and npm tag.
- **Documentation.** Reorganize English and Chinese guides, refresh screenshots, audit historical changelog coverage and document version and release practices. Ignore local pnpm cache and data directories.

## Install

```bash
npm install -g tnega@0.4.7
```

Windows: download **Tnega-Setup-0.4.7.exe** from this release, or let an installed client update itself (Settings → Check for updates).

Requires Node.js >= 22.19.0 for the CLI. Before the first launch, exit any older CLI process that may still write project-local logs. Desktop in-app updating exits the previous desktop runtime before installing.

## Validation

- TypeScript checks, lint, all 28 desktop tests and package artifact checks pass.

Existing failures cover older mode/slash-command/Session event expectations, HTTP fixtures and SSE lifecycle assertions. They remain test debt rather than being silently marked passing.
