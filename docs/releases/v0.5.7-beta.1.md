# Tnega v0.5.7-beta.1

The first preview of 0.5.7 lands the v2 shape: a daemon that serves another
machine's files and commands, seams for files, processes, Sessions and blobs,
image bytes in the blob store, microVM boxes on E2B, and replies that can carry
files or a small interactive UI. Local mode keeps its existing files and
behaviour; no Session migration is needed.

## Features

- **The agent can run on another machine.** `tnega daemon --server <url>` dials
  a tnega host over WebSocket and serves chosen folders, commands, terminals,
  a browser and opt-in computer use there. The protocol carries handshake,
  version and capabilities, cancellation, heartbeats and reconnects; a dropped
  socket resumes queued streams instead of failing them.
- **Seams for files, processes and state.** `ctx.fs`, `ctx.process`,
  `ctx.sessionStore` and `ctx.blobs` replace direct filesystem, child-process
  and log access above them. Local Providers preserve today's behaviour, remote
  Providers bind a Session to a daemon, and the host and four other consumers
  now read Sessions through the store.
- **Session images in the blob store.** Session format 11 stores image bytes
  once under `ctx.blobs` and keeps only the hash in the log. Replay and client
  snapshots restore the bytes, and a byte-bounded cache avoids re-reading every
  screenshot when a long Session is viewed.
- **MicroVM boxes.** `ctx.machines` starts a box from the workspace's
  `.tnega/environment.toml`, runs setup through its daemon, and sends the box's
  traffic through a per-box egress proxy with an allowlist and optional key
  injection. Paused boxes keep memory and disk; a repeated start for the same
  machine key returns the same box.
- **Reply with files and interfaces.** `send_file` attaches a workspace file,
  and `show_ui` renders an A2UI subset such as text, choices, forms, tables and
  cards in clients that support a surface.

## Fixes

- Session storage now serializes leases, repairs a torn tail before appending,
  waits for an append under way before release and disposal, refuses leases
  after close, and keeps one writer's lock file during a handover. Reading a
  deleted Session is skipped without hiding other errors, missing Sessions
  answer 404 instead of being created, and `patchMeta` is retry-safe.
- The daemon orders resumed streams and early process exits, tracks terminal
  disconnects, refuses a terminal in a missing folder, follows the daemon's OS
  path rules, exits when close fails, and removes its token from the served
  environment. Agent-chosen text no longer rewrites the daemon terminal.
- The E2B Provider runs one daemon per box from the v2 template, keys creates
  on the daemon token, serializes starts for one machine, refuses short or
  NUL-containing setup secrets, redacts setup-start errors, and applies an
  address-only box firewall with an API timeout.
- The MXC sandbox makes host temp roots writable, the web app is served from a
  standalone checkout build, and a Session link from another workspace explains
  the mismatch.
- Automatic approval raises the project-constraints budget from 8,000 to
  50,000 characters, so a long project brief no longer forces every call to a
  person.

## Other

- The new `fs`, `process`, `daemon`, `session-store`, `blobs` and `machine`
  packages and their remote/local Providers are published as `tnega/*`
  subpaths. `@tnega/execution` stays as a deprecated forwarder for one version.
- `pnpm try:v2` exercises the daemon, a DeepSeek agent, the JSONL store, blobs,
  a terminal and a reconnect against real processes.
- GitHub Actions remains paused to manual runs. Pushing this tag does not start
  a release; a hand-run publishes npm under `preview` and desktop preview
  clients from `beta.yml`.

## Install

```bash
npm install -g tnega@0.5.7-beta.1
```

Desktop: download **Tnega-Setup-0.5.7-beta.1.exe** (Windows),
**Tnega-0.5.7-beta.1-arm64.dmg** / **Tnega-0.5.7-beta.1-x64.dmg** (macOS,
Apple silicon / Intel) or **Tnega-0.5.7-beta.1-x86_64.AppImage** /
**Tnega-0.5.7-beta.1-amd64.deb** (Linux) from this release. Installed Windows
and Linux clients update themselves (Settings → Check for updates); macOS
builds are unsigned, so they point to the new download instead.

This is a prerelease: select **Preview** under Settings → Update channel to
receive it, and note that a preview install does not downgrade when you switch
back to Stable.
