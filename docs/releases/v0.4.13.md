# Tnega v0.4.13

- **Complete replies after reconnecting.** Session queries keep reporting a run as active if it finishes while history is being read, so clients fetch the final reply on their next poll.
- **Thread permission decisions reach their parent.** When automatic review cannot decide, the exact tool call waits while a permission request is sent to its direct parent. The parent can approve that call once, deny it, or forward it to the user. Approval resumes the original call without a retry. Cancellation, expiry and Project shutdown invalidate pending requests; decisions are audited without changing permission presets or treating agent messages as human authorization.
- **Complete human approval details.** Escalated Thread requests retain the full input, and shell approval cards show working-directory and other execution parameters alongside the complete command.
- **Long-lived processes in Background Tasks.** Chats and Projects show workspace process status, start time and refreshing logs, offer local URLs in the Browser workbench, and provide Stop for the process tree. Output remains available after a process stops.
- **Browser recovery after the last tab closes.** Desktop Agent attachment and address-bar navigation create a replacement page instead of continuing to use a closed tab.
- **Reliable release publication.** The publisher waits for a newly accepted npm version to become visible before publishing the verified GitHub draft.

## Install

```bash
npm install -g tnega@0.4.13
```

Windows: download **Tnega-Setup-0.4.13.exe** from this release, or let an installed client update itself (Settings → Check for updates).

This is a stable release. Use Settings → Update channel → Stable and Check for updates.

Session formats remain compatible; the new approval/delegation metadata needs no migration. Waiting tool executions and process records are not restored after process restart. Close old desktop/CLI processes before using the updated client so both versions do not write to the same histories.
