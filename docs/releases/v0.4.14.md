# Tnega v0.4.14

- **Clear reasons when a tool call fails.** Errors follow their cause chain (`fetch failed: getaddrinfo ENOTFOUND host`), keep system codes and are never empty. Unknown tool names suggest the closest real one, bad arguments name the problem and the expected call shape, and an approval nobody answered says so instead of reading like a refusal.
- **Background jobs run long-lived commands.** `job_start` with `tool: "shell"` starts dev servers and watchers without a deadline, returns once they run with their first output and local URL, and `job_output` reads new output. The separate `process_*` tools are gone. The Background tasks list shows running work first with elapsed time, links and live output, and folds finished work.
- **A calmer conversation while the agent works.** The agent's own words stay in view and its tool calls fold behind one line naming the current step; when the turn ends, everything before the final message folds into one line.
- **Links open where they belong.** Links to workspace files (including `path:line`) and file names in inline code open in the Workbench; local dev server URLs open in the Workbench browser.
- **Usage and cost.** Settings → Usage shows input, cached and output tokens, the cache hit share and estimated cost for today, the last week and all time, by model; the context meter adds cached and reasoning tokens and the session's cost. Prices are set per model. Anthropic-protocol usage now counts cached prompt tokens.
- **Network access behind proxies.** Web requests and skill installs follow `HTTPS_PROXY` / `HTTP_PROXY`, the desktop system proxy, or a proxy set in Settings → Tools & shell → Network. Allowed hosts (GitHub, npm and PyPI by default) work even when a fake-IP proxy answers DNS with `198.18.x.x`, and failures say what went wrong.
- **Long sessions compact themselves.** Past 75% of the context window the agent asks the model whether the run is nearly done: if so it keeps its full context up to 90%, otherwise it compacts at once and keeps the newest 16% word for word.
- **No more stopping mid-task.** A turn that ends on "Let me run the tests:" without the tool call, or with no answer, is reminded to continue or answer, at most twice per turn.
- **Sign in with ChatGPT.** Use a ChatGPT plan instead of an API key, as the Codex CLI does, through a new OpenAI Responses API adapter. Tested against mocked endpoints only.
- **CodeMode and the sandbox.** End-to-end tests cover approvals for tools a `run_code` script calls, sandbox confinement and approved escalation; approval cards say when a CodeMode script made the call.
- **Desktop polish.** The app icon is the Tnega cloud; notices are quieter (weather-only badge, no flashing, a soft chime); clicking Update shows an updating card; the terminal copies and pastes with Ctrl+C / Ctrl+V and has a right-click menu; the agent's browser clicks wait for dropdowns and steer native selects to `browser_select_option`.

## Install

```bash
npm install -g tnega@0.4.14
```

Windows: download **Tnega-Setup-0.4.14.exe** from this release, or let an installed client update itself (Settings → Check for updates).

This is a stable release. Use Settings → Update channel → Stable and Check for updates.

Session formats remain compatible. Agents that called `process_start` / `process_output` / `process_list` / `process_stop` now use `job_start` with `tool: "shell"`, `job_output` and `job_kill`; old histories that contain those calls still load. System Config gains optional `network` and per-route `pricing` and `auth` fields; older files need no change. The npm package now depends on `undici`, loaded only when a proxy is in use. Close old desktop/CLI processes before using the updated client so both versions do not write to the same histories.
