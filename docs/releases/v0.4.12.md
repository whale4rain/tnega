# Tnega v0.4.12

- **Automatic publication from tags.** A prepared version tag builds and checks the npm package and Windows installer in GitHub Actions, then publishes their verified bytes to npm and GitHub. Preview and stable channels remain separate.
- **Runs survive a closed browser connection.** Closing a session's live event stream no longer cancels its reply; use Stop when you want to cancel the run.
- **Projects as a team room.** Messages are grouped by author and time with day separators, the coordinator shows "is typing" while it writes, and hovering a thread card lets you reply to that thread directly. Agents are told who is speaking and which message a reply answers.
- **Board, Library and Routines.** The project panel is the same Workbench a session uses, with Board, Library and Routines as its first tabs; threads and project settings open as tabs, and Files, Changes and Terminal stay available. Ctrl+J toggles it.
- **The Board.** It replaces Overview: today's activity (threads opened, finished, outputs, tokens) and lanes for Needs you, Working, Ready and Idle. Each card shows its step or question, checklist progress, outputs, active time and tokens. Resolve a thread once you have taken its result; resolved threads fold away and come back when they get a new message.
- **Routines.** Put recurring work on a schedule (daily, weekdays, weekly or every few minutes) from the Routines tab or by asking the coordinator. Each run goes to the routine's own thread. Routines run while Tnega is running and the project has been opened.
- **More kinds of artifacts.** Threads can publish workspace files such as Word, PowerPoint, Excel, PDF and images. The Library filters by type and previews them with the same viewers as workspace files.
- **Threads stop asking you.** Thread tool calls are reviewed automatically for the coordinator, using what you said in the room as evidence. Anything not approved goes back to the thread, which asks its coordinator; the coordinator asks you only when the decision is yours.
- **Several chat models.** Settings → Models registers several chat models and picks the default; sessions still switch from the composer. Your existing model becomes the first entry. Approval reviewers stay under Approvals.
- **Dev servers in the Windows sandbox.** Programs that start child processes and read their output (`npm run dev` with vite or esbuild, many test runners) cannot run inside the write sandbox. Tnega now says so where it happens, including a dev server that looks ready and fails its first request, and the agent can ask to run that one command outside the sandbox with a reason. The approval card says "Runs outside the sandbox" and shows the reason; the command leaves the sandbox only after you approve.
- **Quieter tool calls.** Tool calls fold behind one line while a turn runs ("Running npm test"), and a finished turn sums them up ("Used 6 tools: 3 reads, 2 commands").
- **Smaller fixes.** Each project's coordinator has its own colour, so projects no longer look alike in the sidebar. Selects have an inset chevron and themed options. The agent browser keeps the address you typed and shows a loading bar. PowerShell progress no longer leaks into command output as a `#< CLIXML` block. Project memory moves into project settings, and the room and threads share a one-line message box that grows as you type.

## Install

```bash
npm install -g tnega@0.4.12
```

Windows: download **Tnega-Setup-0.4.12.exe** from this release, or let an installed client update itself (Settings → Check for updates).

This is a stable release. Use Settings → Update channel → Stable and Check for updates. After clicking Update, wait for installation and automatic restart before opening a shortcut again.

Session formats are unchanged. `config.json` gains an optional `models` list; adding the first model through Settings moves your existing model into it, and configs without it keep working. Project Blackboards gain `routine` facts and threads a `resolved` state; older projects read as having neither.
