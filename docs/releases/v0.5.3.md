# Tnega v0.5.3

This release follows 0.5.2 with settings you can change while a turn runs,
search over your past sessions, calmer step rows and two sandbox fixes.

## Features

- **Change model, effort and access while a turn runs.** The model, reasoning
  effort, permission level and approval mode no longer need a new turn: the step
  that is already talking to the model keeps its settings and the next step uses
  the new ones, so the request and its replay agree. The timeline shows each
  change as one quiet settings line, inside the turn ("applies from the next
  step") or between turns. Agent type and mode still wait for a new turn.
- **The agent can search your past sessions.** `search_sessions` finds sessions
  by title or message text across every workspace the app lists and ranks them
  by match strength; `search_session` finds the matches inside one session and
  `read_session` reads around a match or pages back. An SQLite index in the
  Tnega home keeps up incrementally, is capped in size and drops the sessions
  used least — naming a dropped session indexes it again. The session menus can
  copy a session link (`tnega://session/<id>?workspace=<path>`) or its id to
  paste into chat. Both tools are read-only and need no approval.
- **Steps read as one calm line.** Thoughts and tool calls between two replies
  fold into a single line that says what was done ("Searched 3 times, ran a
  command · 12s"). Step rows lose the card and the fill, and an opened step
  hangs from one rail.
- **The sandbox reads the machine instead of only the workspace.** Under MXC the
  sandbox now hands every volume root in as a read root, so node, npm and
  PowerShell work wherever they were installed (PowerShell before 7.7 also needs
  `C:\` readable to start at all). Writes stay confined to the workspace, the
  same write-only restriction the ACL runner always had. `mxcRead: 'roots'`
  turns read-side confinement back on.

## Fixes

- A permission switch now reaches the resident runtime and the model. The level
  is part of the resident signature and a permission-only change retires the
  runtime, so subagents stop using the old level; the switch also appends a
  durable system message naming the new level, so the model no longer asks for
  escalations its level already grants — which an auto review then approved
  outside the sandbox.
- An MXC executor installed under a custom npm prefix is found again: the lookup
  reads `NPM_CONFIG_PREFIX` / `npm_config_prefix` and the `node_modules` beside
  each `PATH` directory, so a `prefix=` in `~/.npmrc` no longer makes the setup
  notice claim MXC is missing.
- With Glass everywhere, the header's bottom border runs under the native window
  controls instead of stopping short of them.

## Other

- New internal packages `@tnega/run-settings`, `@tnega/session-search`,
  `@tnega/session-search-sqlite` and `@tnega/tool-session-search`; the host owns
  one session index and mounts the session tools over the workspaces it lists,
  replacing `@tnega/tool-sessions`.
- When upgrading from 0.5.2, the first search builds the session index; it lives
  under the Tnega home and can be deleted at any time.

## Install

```bash
npm install -g tnega@0.5.3
```

Desktop: download **Tnega-Setup-0.5.3.exe** (Windows), **Tnega-0.5.3-arm64.dmg** / **Tnega-0.5.3-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.3-x86_64.AppImage** / **Tnega-0.5.3-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.
