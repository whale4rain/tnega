# Tnega v0.5.6-beta.1

The first preview of 0.5.6 brings two new capabilities: an agent that can ask for
a secret it can use but never see, and a command sandbox that can be limited to
listed domains. Both are preview-only for now — check them on a Preview channel
install before they reach Stable.

## Features

- **The agent can ask for a secret without seeing it.** When a task needs a key,
  the agent asks with `ask_user_question` and a `secret` name such as
  `GITHUB_TOKEN`. The question card is a single hidden input with a show/hide
  toggle and a **Remember** button; the value goes straight to the host's secret
  store, and the agent only learns the name. Commands get it as an environment
  variable, so `$env:GITHUB_TOKEN` (PowerShell) or `$GITHUB_TOKEN` works. A
  session secret lives until the session is deleted or tnega exits; **Remember**
  saves it for the workspace in `~/.tnega/secrets.json` (owner-only, `0600`) so
  every session there starts with it. Settings → Secrets lists the names and
  removes one; it never shows a value, and secret values are masked in tool
  output and live progress as `[secret: NAME]`, plain and in base64, base64url
  and URL-encoded form. A value a command was given stays masked even after the
  secret is removed or replaced.
- **Command network rules.** Settings → Tools & shell → Command network chooses
  what sandboxed commands may reach: `open` (unchanged behaviour), `off`, or
  `allowlist` with allowed and denied domains. An allowed entry is `example.com`,
  `*.example.com` (subdomains only), an IP literal, or any of those with `:port`
  or `:*`; deny wins over allow, and anything unlisted is refused. **No port
  means every port** in both lists: `example.com` and `example.com:*` are the
  same, while `example.com:443` matches only 443. Each command reaches the
  network through a filter proxy the host runs on loopback — Linux gets it over
  a bind-mounted Unix socket, macOS and Windows over a loopback port that the
  sandbox permits — and allowed connections can chain through the network proxy
  already set in Settings. A refused command's stderr names the blocked host and
  says to ask the user, and the agent can call `request_network_access` to ask
  for it on the usual approval card; an approved host applies to the rest of the
  session, and **remember** also writes it to Settings. `off` and the deny list
  cannot be opened by an approval, and `*` is never granted. The command's
  traffic is filtered at the destination level only: allowing `github.com`
  allows everything inside that tunnel, and a client that ignores proxy
  environment variables simply has no network.
- **The agent can ask for a blocked domain.** `request_network_access` exists only
  where the host can read and write those settings; it always goes through the
  approval card, and asking for a domain on the deny list changes nothing.

## Fixes

- Settings passes the open session to the Secrets section only while browsing
  sessions, so Projects mode no longer lists the secrets of a session that is
  not on screen.
- A saved secret named `__proto__` is kept, and inherited names such as
  `toString` are no longer reported as removed when they were never stored.
- Secret names that would change what a command loads or runs are refused:
  families `LD_`, `DYLD_`, `NPM_CONFIG_`, `JAVA_`, `_JAVA_`, `GIT_CONFIG_`, plus
  `JDK_JAVA_OPTIONS` and the Git variables that steer execution. `GIT_TOKEN` and
  similar names are still allowed.
- A damaged or unexpected `secrets.json` reports the file path instead of being
  silently dropped on the next save, and rewriting the file keeps every
  workspace's keys.
- The command filter proxy refuses a host it is about to block **before** it
  resolves it, so a blocked name never leaks to DNS, and it also refuses cloud
  instance-metadata endpoints that live outside link-local
  (`100.100.100.200`, `168.63.129.16`, `192.0.0.192`, `fd00:ec2::/32` and
  similar) plus the host's own interface addresses — a service bound to
  `0.0.0.0` answers on the LAN address exactly as on loopback. Both remain
  recoverable: a rule that names the host literally skips that check, so
  allow-listing `192.168.1.10:3000` works while `*.corp.internal` does not.
- WebSocket traffic works through the filter proxy. An upgrade request used to
  reach the origin as an ordinary request and come back `200`, leaving the
  client stuck after "connected"; the checked target now receives a real upgrade
  and the connection becomes a byte tunnel.
- A refused command's note describes only that command. A background job or a
  sibling command hitting a different host no longer appears in it, so the agent
  asks for the domain it actually needed.
- Sandbox grants, upstream checks and settings loaded late are hardened: an
  approval cannot widen a narrower policy, and a saved network setting that
  arrives after the run starts is still honoured.

## Other

- `@tnega/secrets`, `@tnega/secrets-local`, `@tnega/execution-secrets` and
  `@tnega/tool-secrets` are new packages, also published as `tnega/*` subpaths;
  `@tnega/sandbox-network-proxy` and `@tnega/tool-network-access` are new, and
  `@tnega/sandbox` gains the `network` policy dimension, `decideNetworkAccess`
  and the `sandbox/network` event.
- ADR 0015 records the secret store's format, lifecycle and permission boundary.
  ADR 0008 records the command-network dimension, why the sandbox has no managed
  policy baseline (tnega does not target organisations yet), and the local
  address set including its documented gaps.
- Design notes describe the secret question card, the Secrets settings section
  and the command network settings.

## Install

```bash
npm install -g tnega@0.5.6-beta.1
```

Desktop: download **Tnega-Setup-0.5.6-beta.1.exe** (Windows), **Tnega-0.5.6-beta.1-arm64.dmg** / **Tnega-0.5.6-beta.1-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.6-beta.1-x86_64.AppImage** / **Tnega-0.5.6-beta.1-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.

This is a prerelease: select **Preview** under Settings → Update channel to
receive it, and note that a preview install does not downgrade when you switch
back to Stable.
