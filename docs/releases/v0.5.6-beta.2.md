# Tnega v0.5.6-beta.2

The second preview of 0.5.6 adds computer use — an agent that reads a window's
accessibility tree, aims at elements instead of guessing pixels, and reports what
its action changed — and takes screenshots out of the request body by uploading
them through the provider's Files API. Computer use ships off by default and
needs the `cua-driver` binary installed separately.

## Features

- **The agent can see and use desktop apps.** Computer use adds `ctx.computer`
  and a `computer_*` tool family: list windows and apps, start an app by name,
  id or executable path, screenshot a window, zoom into a region, then click,
  type, press a key, scroll, drag, hover, invoke a menu item, run a batch of
  steps, read and write the clipboard. It is off until **Settings → Computer
  use** is on, and it needs the `cua-driver` binary (not bundled): the host looks
  for `computerDriverPath`, then `TNEGA_CUA_DRIVER`, then `PATH`, then the
  installer's folder, and fails with an install command rather than falling back
  to another input path. Actions default to background delivery and only retry in
  front when the driver refuses the event kind — a re-sent event is how one
  keystroke becomes two.
- **Aim at elements, not pixels.** `computer_read_tree` reads a window's
  accessibility tree as text, each actionable row tagged `[N]` with an element
  token `<snapshot>:N`; click, scroll, type and single keys take that token
  instead of a point, so the driver invokes the element itself and can confirm
  the result. Element and point are mutually exclusive. A token from an older
  read is refused with a hint to read again, never silently retried. This costs
  no screenshot.
- **An action says what it changed.** When the driver cannot confirm an effect,
  the result carries the driver's own comparison with the caller's previous read:
  `3 added, 0 changed, 1 removed` plus the differing rows, or an explicit
  "the window did not change" — including, for posted input on a target that may
  ignore it, a warning that the click probably did not land. A change that shifts
  rows also reports the renumbering, so old tokens are not reused. A confirmed
  action pays nothing extra.
- **Row boxes on request.** `computer_read_tree` accepts `frames: true` to append
  each row's box in the pixels an action takes, for grids, rows and columns, and
  for popup rows that carry no element token. It costs one screenshot per read.
- **Hover, clipboard, apps, menus and batches.** Hover moves the *real* pointer
  (a window-scoped cursor is an overlay apps never see), with the window brought
  forward. Clipboard read/write share their own `computer:clipboard` grant.
  `computer_list_apps` names each app's id so "chrome" means that app.
  `computer_menu` resolves a native application menu by label path; menus a page
  or an Electron or WinUI app draws itself are not supported and say so.
  `computer_steps` runs several actions in one call, judged step by step, and
  each step that ran is audited.
- **Screenshots are budgeted per Session.** `computerMaxScreenshots` bounds the
  screenshots one Session may take; screenshots, zooms, waits and the image after
  each action all count. The count is rebuilt from the Session's own tool
  results, so a restart does not refill it. Once spent, actions still run but
  answer without an image, and the looking tools point at `computer_read_tree`.
- **Text-only models get the tools without screenshots.** The host answers
  whether the model behind the next step can see images, asked before every
  screenshot because the model can change mid-run; when it cannot, results
  describe the window in one line and spend no budget.
- **Images no longer travel in the request body.** Screenshots and other images
  are uploaded once to the route's Files API (keyed by SHA-256, so the same bytes
  are uploaded once and the id stays stable across turns) and referenced by id:
  `{type:"file"}` for chat completions, `input_image.file_id` for Responses, and
  a file source with the `files-api-2025-04-14` beta for Anthropic. Measured on a
  1024 screenshot: 402 KiB uploaded once, request body down from ~400 KiB to
  138 bytes, and a sliding image window no longer changes the prompt prefix.
  `filesApi` (`auto` / `off` / `required` / `openai` / `anthropic`), `filesUrl`
  and `filesPurpose` control it; an endpoint without a Files API is remembered
  instead of retried every turn.
- **`maxImages` bounds the images a request carries.** Set it at the top of the
  config or on one model route (the route wins). Each image is billed again on
  every request, so a screenshot-heavy task wants a small number: 2 is enough for
  computer use.
- **Responses turns can chain.** With a route that keeps state, the adapter sends
  `store` and `previous_response_id` and only the new turns; only a strict prefix
  of the conversation is chained, so a compaction or an edited message resends
  everything. A route that says it did not store the response turns state off by
  itself, and DeepSeek's stateless Responses endpoint is never sent those
  parameters at all.
- **The Context tool shows what each tool cost.** The session context report has
  a per-tool row: calls, failures, time, images its results carried, and the
  prompt and completion tokens of the requests that read those results, split
  evenly when one request read several. The Context tool lists them under
  "By tool".

## Fixes

- One refused image no longer costs a route its vision. Only an error about the
  model's own input (`does not support image`) counts; a rejected upload, a file
  id this account does not own or an oversized image is a problem with that
  image, and a different set of images is tried again rather than staying
  text-only for the life of the adapter.
- A route's `fetch` covers every request it makes — completion, upload and model
  list. Previously only the upload used it, so an injected transport saw the
  upload and the completion escaped to the global fetch.
- A minimized window is restored before it is read or acted in, and input the
  driver delivered but could not confirm is never re-sent.
- Hover is refused outside the window's screenshot instead of moving the user's
  pointer onto another window, and never acts on rows a diff read marks as
  removed.
- A screenshot slot is held before capturing, so screenshots taken side by side
  cannot overrun the budget.
- `tnega run` reads the image budget from the route it actually uses, not the
  top-level setting.
- Global memory lives in the Tnega home (`TNEGA_HOME`), so an isolated
  installation or a test run no longer reads and writes the user's own
  `~/.tnega/MEMORY.md`; the "memory is full" error names the file it refused.

## Other

- The test suite is split into two layers: `pnpm test` runs the code layer (no
  credentials, build artifact, GUI or elevated privilege), and
  `pnpm test -- --全量` (or `pnpm test:all`) adds the host layer as a second
  sequential pass, since a full build and GUI tests starve under the parallel
  load of ~280 files. A test joins the host layer by being named
  `*.e2e.test.ts` or `*.smoke.test.ts`.
- New packages: `@tnega/computer`, `@tnega/computer-cua`, `@tnega/tool-computer`
  and `@tnega/llm`'s Files API module, all published as `tnega/*` subpaths.
- ADR 0016 records the computer seam, the element pathway, the feedback loop and
  the driver's menu limits; the real-provider verification notes cover what was
  measured on Windows and Linux.

## Install

```bash
npm install -g tnega@0.5.6-beta.2
```

Desktop: download **Tnega-Setup-0.5.6-beta.2.exe** (Windows), **Tnega-0.5.6-beta.2-arm64.dmg** / **Tnega-0.5.6-beta.2-x64.dmg** (macOS, Apple silicon / Intel) or **Tnega-0.5.6-beta.2-x86_64.AppImage** / **Tnega-0.5.6-beta.2-amd64.deb** (Linux) from this release. Installed Windows and Linux clients update themselves (Settings → Check for updates); macOS builds are unsigned, so they point to the new download instead.

Computer use needs the `cua-driver` binary from <https://cua.ai/docs/cua-driver>; it is not bundled, and the tools stay hidden until you turn it on in Settings.

This is a prerelease: select **Preview** under Settings → Update channel to
receive it, and note that a preview install does not downgrade when you switch
back to Stable.
