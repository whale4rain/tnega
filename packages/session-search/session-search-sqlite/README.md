# `@tnega/session-search-sqlite`

Session 搜索缝的 Provider：`node:sqlite` 上的 FTS5 索引。

- **位置**：默认 `<tnega home>/session-index.sqlite`，宿主创建一个 `SqliteSessionIndex` 供所有 run 共用，第一次搜索时才打开，宿主关闭时关闭。它只是 Session 文件的缓存，从不写 Session；版本不符时整个重建。
- **匹配**：trigram 分词，忽略大小写的子串匹配，中英文都适用；查询里的每个词都要出现。少于三个字符的词（例如两个汉字）退回子串扫描。查询文本永远是数据，FTS 语法不会生效。
- **排序**：按 Session 汇总 bm25 分数，命中越多、越相关越靠前，标题命中加权；同分按更新时间。
- **增量**：每次搜索前比对文件大小与修改时间，只读变化过的 Session；变长的从上次的 seq 往后追加，变短（回退）的整份重建，文件没了就删掉。
- **上限与淘汰**：`maxChars`（默认 2000 万字符）。超过时按使用次数淘汰，用得最少的先走，次数相同再看上次使用时间与更新时间；`keepUsedWithinMs`（默认 1 小时）内用过的不淘汰。每次淘汰把所有次数减半，让很久以前的使用逐渐失效。出现在搜索结果里计 1 次，在其中搜索或阅读计 2 次。
- **重新索引**：被淘汰且没再变化的 Session 不会在后续搜索中自动回来；用户贴出它的链接、Agent 在其中搜索或阅读它时，会立即重新索引。
