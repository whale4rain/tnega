# `@tnega/artifact-local`

`ctx.artifacts` 的本地 Provider：内容寻址的文件树。

## 落盘形状

```
<root>/<hash 前两位>/<hash>            # 内容
<root>/<hash 前两位>/<hash>.meta.json  # { size, mediaType }
```

`<hash 前两位>` 只是为了让一个目录别堆上万个文件，不参与寻址语义。

## 取舍

- **写一次，不改**。内容按哈希落盘后不再变化；`mediaType` 是内容附带的第一份声明，
  同内容再 `put` 一次不会改掉它 —— 引用必须稳定，否则同一个哈希会解释出两种类型。
- **先写临时文件再改名**。崩在写入中间只会留下一个 `.tmp`，读者永远看不到半份内容。
  并发写同一哈希是幂等的：目标已经就位（另一个写入者先到、内容必然相同）就算成功；
  Windows 上并发替换会短暂 `EPERM`/`EACCES`/`EBUSY`，因此先重试再接受已经就位的文件，
  不让输掉竞争的一方把一次正常的并发发布报成失败。
- **先内容后元数据**。`meta.json` 存在就意味着内容已经就位，`stat` 因此不需要两次探测。
